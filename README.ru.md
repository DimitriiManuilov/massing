# МАССИНГ

Инструмент для архитекторов и градостроителей: выбираешь прямоугольник на карте
любого города мира — получаешь объёмно-пространственную модель участка в браузере.
Серый массинг, мягкий свет, реальное солнце на заданную дату, рельеф, расчётные
показатели плотности. Дальше — фотореалистичный рендер, аналитическая записка или
проектные объёмы через нейросеть по твоему API-ключу.

Всё считается локально. Своего сервера у инструмента нет.

## Запуск

```bash
cd ~/msk_massing
./serve.sh          # откроет http://localhost:8765
```

Через `file://` не заработает: ES-модули, веб-воркер и запросы к Overpass требуют
http-происхождения. Порт можно передать аргументом: `./serve.sh 9000`.

При первом заходе участок уже намечен — достаточно нажать «Построить модель»,
чтобы увидеть результат. Дальше карта открывается там, где ты работал в прошлый раз.

## Как пользоваться

**Шаг 1 — местность.** Найди место через поиск или возьми готовый город из списка.
Клик по карте ставит центр участка, протяжка от центра задаёт радиус на глаз,
ползунок — точно (100–1200 м). Карта двигается с зажатым <kbd>Shift</kbd>, масштаб —
колесом. Рабочий радиус — 200–350 м на квартал; выше 700 м загрузка затягивается,
а детали сливаются на общем плане.

**Шаг 2 — редактор.** Панель справа разделена на вкладки: «Сцена» (солнце, камера,
слои), «Участок» (показатели), «Нейросеть».

Участок показывается керном: вырезанный из города цилиндр — сверху рельеф с
застройкой, по краю видна толща грунта, снизу дно. Он висит в пустом градиентном
фоне, как макет на витрине. Отсюда и подача, и отсутствие проблемы с обрывающейся
на горизонте землёй.

| Что | Как |
|---|---|
| Вращать, приближать | мышь: левая — орбита, колесо — зум, правая — панорама |
| Вернуться к выбору | кнопка «← местность» слева вверху |
| Узнать про здание | клик по объёму — карточка с высотой, этажностью, адресом, отметкой земли |
| Солнце | дата, местное время и часовой пояс — тени пересчитываются сразу |
| Ракурсы | Изометрия / План / С земли (уровень глаз пешехода) |
| Проекция | перспектива или аксонометрия |
| Экспорт | PNG (×2), OBJ (застройка + проектные объёмы), GeoJSON (проектные объёмы) |

Тумблер «Отметить оценочные высоты» красит тёплым тоном здания, у которых в OSM
не было ни `height`, ни `building:levels` — сразу видно, какой доле модели верить
нельзя.

## Страница-кейс

`case.html` — презентация проекта для портфолио: задача, решение, галерея,
архитектура, таблица инженерных решений, честный разбор ограничений. Двуязычная,
переключатель RU/EN в шапке, язык запоминается. Открывается по ссылке «о проекте»
внизу панели выбора или напрямую: http://localhost:8765/case.html

Картинки берутся из `examples/` — если пересобираешь галерею, клади новые кадры
туда под теми же именами (`case_iso.png`, `case_top.png`, `case_eye.png`,
`case_proposal.png`, `case_barcelona.png`).

### Про надёжность Overpass

Публичные серверы Overpass регулярно уходят в перегрузку и отвечают 504 — это
главный источник ощущения «инструмент тормозит». Что сделано:

- **Четыре зеркала по очереди**, отсортированные по замеренной скорости:
  `maps.mail.ru` (1.4 с), `overpass.osm.ch` (1.7 с), `overpass-api.de` (4.4 с),
  `kumi.systems`. На каждое даётся 35 секунд, потом сразу следующее.
- **Параллельную гонку по зеркалам пробовали и откатили**: Overpass отвечает на
  одновременные запросы с одного адреса ошибкой 406. Последовательный обход
  быстрее и честнее по отношению к чужому бесплатному сервису.
- **Кэш подхватывает покрывающие выборки.** Сдвинули центр на десяток метров или
  уменьшили радиус — раньше это был новый запрос на десятки секунд, теперь берётся
  ранее сохранённая область, если она целиком накрывает нужную и не больше её
  вчетверо. Повторная сборка участка — около полусекунды.
- Если молчат все зеркала, инструмент говорит об этом прямо и предлагает повторить
  через минуту, а не висит с неподвижной полосой.

Часовой пояс подставляется по долготе, то есть время истинное солнечное, а не
административное. Для геометрии теней это честнее; если нужен «как на часах»,
подвинь ползунок пояса.

## Нейросеть

Кнопка «ключ и модель» в панели справа. Ключ хранится **только в localStorage
этого браузера** и уходит напрямую выбранному провайдеру.

| Провайдер | Рендер | Записка | Объёмы |
|---|:--:|:--:|:--:|
| Anthropic (Claude) | — | ✓ | ✓ |
| Google Gemini | ✓ | ✓ | ✓ |
| OpenAI | ✓ | ✓ | ✓ |
| fal.ai | ✓ | — | — |

- **Фотореалистичный рендер** — текущий кадр уходит в image-to-image с указанием
  сохранить геометрию, ракурс и направление теней; возвращается визуализация.
  Освещение выбирается списком (день, закат, ночь, зима, после дождя).
- **Аналитическая записка** — кадр плюс расчётные показатели превращаются в разбор
  среды: тип застройки, чтение цифр, планировочная структура, проблемные места,
  аналоги. Сохраняется в Markdown.
- **Проектные объёмы** — задание из поля «Уточнение к запросу» («квартал 8 этажей,
  периметральная застройка вдоль набережной») превращается в многоугольники с
  высотами, которые встают в сцену терракотовым цветом. Модель получает габариты
  существующих пятен и границы участка, чтобы не ставить объёмы поверх домов.
  Выгружаются в GeoJSON для QGIS.

Запросы оплачиваются по тарифу провайдера. Заводи отдельный ключ с лимитом:
страница исполняет сторонний код (Leaflet, three.js), и ключ в браузере в принципе
доступен расширениям.

## Устройство

```
index.html          два экрана: карта выбора и сцена
serve.py, serve.sh  локальный сервер без кэширования
app/
  main.js           карта, UI, оркестрация, вызовы моделей
  worker.js         фоновый поток: сеть → разбор → триангуляция
  overpass.js       запрос и классификация объектов OSM
  geo.js            проекция, разбор высот, кольца мультиполигонов
  terrain.js        тайлы высот → сетка рельефа
  build.js          обрезка, экструзия, слияние геометрии, статистика
  scene.js          свет, материалы, камера, постобработка, экспорт
  sun.js            положение солнца (NOAA)
  cache.js          IndexedDB
  ai.js             провайдеры моделей
  style.css
vendor/             three.js r169, Leaflet 1.9 — локально, без CDN
```

Тяжёлое живёт в воркере, наружу уезжают типизированные массивы без копирования.
Сцена перерисовывается только когда что-то изменилось; во время вращения падает
разрешение и отключается постобработка, в покое качество возвращается; карта теней
пересчитывается лишь при смене солнца.

Постобработка: **GTAO** (объёмное затенение по горизонту — чище и дешевле прежнего
SSAO), SMAA и собственный проход **tilt-shift** — узкая полоса резкости плюс
виньетка и зерно. Последнее не украшение: малая глубина резкости читается мозгом
как макросъёмка, и керн начинает выглядеть макетом на столе. Оба эффекта
переключаются в слоях.

В левом нижнем углу — счётчик времени кадра. На Эшампле (747 зданий, 22.5 тыс.
треугольников, полотно 2174×1188 при удвоенном пиксельном отношении): около
**8 мс на кадр** при полном качестве и **4 мс** во время вращения. Замерять надо
через `readPixels` — иначе меряется постановка команд в очередь, а не работа GPU.

Для отладки из консоли: `massing.viewer`, `massing.stats`, `massing.site`.

## Возраст застройки и морфотипы (Москва)

Для Москвы подключён открытый датасет **how-old-is-this.house** (ODbL,
версия 15.10.2022): год постройки для 124 219 зданий. Стомегабайтный
GeoPackage урезан до 1.2 МБ — долгота, широта и год на здание, файл лежит
в `data/moscow_ages.bin`. Дом OSM связывается с записью по ближайшему
центроиду в радиусе 30 м; на пробном участке год находится примерно
у 85 % зданий.

Год задаёт морфотип, а морфотип — пропорции, которые видно даже в сером
массинге:

| Период | Тип | Высота этажа | Кровля | Карниз |
|---|---|---|---|---|
| до 1917 | дореволюционная | 3.6 м | скатная | 0.55 м |
| 1918–1932 | конструктивизм | 3.0 м | плоская | — |
| 1933–1955 | сталинская | 3.3 м | скатная | 0.75 м |
| 1956–1968 | хрущёвка | 2.6 м | плоская | — |
| 1969–1991 | поздний СССР | 2.75 м | плоская | — |
| 1992–2010 | постсоветская | 3.0 м | плоская | — |
| 2011+ | современная | 3.15 м | плоская | — |

Сталинка выше хрущёвки не потому, что этажей больше, а потому что этаж
3.3 м против 2.6 — при одинаковой этажности разница в треть высоты дома.
Карниз и цоколь строятся поясами, выступающими за плоскость стены: у
сталинского дома вынос доходит до метра и читается на общем плане, у
панельного его практически нет.

Год и тип показываются в карточке здания. Границы периодов взяты по
перелому в строительной практике: 1955-й — постановление об излишествах,
1957-й — начало серийного крупнопанельного домостроения.

**Атрибуция обязательна:** © how-old-is-this.house, 2020 (ODbL). Лицензия
вирусная — производные тоже под ODbL, что совпадает с условиями OSM.

## Что делает объём зданием

Референс — клеевой макет: почти белые объёмы, мягкий рассеянный свет,
длинная неглубокая тень. Масштаб задают не текстуры и не окна, а
силуэт.

**Свес кровли** в полметра с лобовой доской. Без него скат упирается в
стену встык, и дом выглядит склеенным из двух коробок.

**Дымники** на коньке — вертикальные штрихи, которые в силуэте квартала
отличают жилую застройку от промышленной.

**Парапет** на плоской кровле: полоска в 35–60 см, но без неё дом
обрывается срезом по линейке.

**Карниз и цоколь** — по эпохе, см. таблицу выше.

Пояса строятся с усом на углах: если смещать каждый отрезок контура по
своей нормали независимо, ленты на углах расходятся и по верху дома идут
зубцы. Вынос уса ограничен вдвое — на входящих углах биссектриса
разворачивается, и без потолка пояс выстреливал шипами. У парапета
обязательна внутренняя грань: он стоит на кровле, а не на стене, и через
открытую щель просвечивала изнанка.

Оконный ритм тоже пробовали — проёмы рисовались в шейдере, с отклонением
нормали на откосах. Работало и почти ничего не стоило, но от массинга
уводило в сторону иллюстрации, поэтому убрано. Пропорции эпох по-прежнему
читаются высотой этажа и выносом карниза.

Свет подобран под тот же макет: заливка неба сильная, солнце умеренное,
экспозиция 0.94. Светотень держится на затенении в примыканиях, а не на
контрасте — провал в тенях сразу выдаёт компьютерную картинку, в
натурном макете его нечем создать.

### Главная ось дома

Куда дом вытянут — вопрос, от которого зависит направление конька,
разворот лифтовой надстройки на кровле и линии, по которым протяжённый
дом делится на секции.

Сначала ось искалась вторым моментом — разбросом вершин контура
относительно центра. Способ короткий и на прямоугольных домах верный,
но он смотрит на вершины, а не на форму. Достаточно, чтобы контур был
размечен неравномерно, и ответ уезжает: у Г-образного дома со сторонами
вдоль осей второй момент даёт диагональ в 45°, и лифтовая шахта на
кровле встаёт наискось к стенам.

Теперь ось ищется минимальным охватывающим прямоугольником. По теореме
о вращающихся штангенциркулях одна его сторона лежит на ребре выпуклой
оболочки, поэтому достаточно перебрать рёбра оболочки — их единицы, и
считается это мгновенно. От разметки контура ответ не зависит вовсе:

| Пятно                        | Второй момент     | Габарит        |
|------------------------------|-------------------|----------------|
| Прямоугольник 40×10 под 30°  | 30°, площадь 400  | 30°, площадь 400 |
| Г-образный дом по осям       | −45°, площадь 2080 | 0°, площадь 1600 |

Побочный выигрыш: `roofPlan` отказывает в скатной кровле, если контур
заполняет свой габарит меньше чем на 78 %. Тесный габарит поднимает
заполнение, и прямоугольные дома, стоящие под углом к сетке координат,
перестали терять кровлю.

### Секции протяжённых домов

Панельный дом в сто с лишним метров — это не один объём, а несколько
секций в ряд, и в натуре они почти всегда разной высоты: серия
допускала секции в пять, девять и двенадцать этажей, на склоне их
сажали ступенями, позже надстраивали неравномерно. Одинаковая по всей
длине коробка выдаёт схему сразу — квартал получается из лент, а не из
домов.

Ступени строятся не разрезанием объёма, а надстройкой: основной объём
остаётся целым, а поверх части секций ложится один-три этажа, вырезанных
из того же пятна полосой поперёк главной оси. Разрезать было бы честнее,
но дороже и без выигрыша в картинке.

Рисунок ступеней выводится из идентификатора здания, поэтому один и тот
же дом при каждой сборке выглядит одинаково — иначе повторный заход на
участок давал бы другой город. Применяется только к серийной застройке
(хрущёвки, поздний СССР, постсоветская): у дореволюционного дома ровный
карниз как раз правда.

На Новых Черёмушках ступени получают 12 домов из 27 подходящих.

### Двор

Половину кадра занимает не застройка, а то, что между домами, и раньше
это было ровное серое пятно: площадки шли по зелени и красились газоном,
а парковок не было вовсе. Теперь твёрдые покрытия — парковки,
спортивные и детские площадки, пешеходные площади — идут отдельным
слоем между зеленью и тротуарами: парковка лежит на газоне, но под
бортовым камнем проезда.

### Надстройки на кровле

Машинное отделение лифта и вентшахта на плоских кровлях домов выше
пяти этажей. В силуэте квартала именно они не дают кровлям слиться в
ровное поле светлых прямоугольников.

### Тени

Рамка карты теней подогнана под участок: раньше она была вдвое шире
круга, и половина карты уходила в пустоту — при том же разрешении тень
была вдвое грубее. Сдвиг по нормали заодно уменьшен с 0.7 до 0.35: с
тесной рамкой самозатенение уже не лезет, а большой сдвиг отрывал тень
от стены у основания.

### Материал макета

Плоский цвет с постоянной шероховатостью выглядит пластиком. Отлитый
макет неоднороден: партии гипса отличаются, у основания стен темнее от
пыли, свет по поверхности ложится не идеально ровно. Из этих долей
процента и складывается ощущение вещи, а не картинки.

- **Разнотон по зданиям**, ±4 % от идентификатора. Без него квартал
  читается одной выдавленной массой, и глазу не за что зацепиться,
  чтобы отделить дом от дома. Отклонение детерминировано, поэтому
  повторная сборка даёт тот же участок.
- **Зерно поверхности** — две октавы значимого шума по мировым
  координатам, поэтому не тянется по граням и одинаково выглядит на
  стене и на кровле. Частоты подобраны под то расстояние, с которого
  на модель смотрят: мелкое зерно в полметра честнее физически, но на
  экране усредняется в ровную заливку. Читаются разводы в несколько
  метров.
- **Пыль у основания** — метр снизу темнее на 16 %.
- **Шероховатость гуляет вместе с зерном**: ровная по всей площади она
  и даёт то самое пластиковое отражение.

Ничего не рисуется — ни окон, ни линий, ни рисунка; меняется только тон
поверхности.

Амплитуду подбирал по кадру: 5 % не видно вовсе, 55 % превращают гипс в
бетон под дождём, 16 % — та мера, на которой поверхность перестаёт быть
заливкой, но остаётся макетом. Третью октаву убрал: после
перебалансировки она на глаз не давала ничего.

**Про цену.** Кадр после этой правки: 12–17 мс в изометрии против
11–15 мс до неё. Разброс замеров на одном и том же коде сопоставим с
самой разницей, так что честно сказать можно только одно — материал
стоит несколько миллисекунд, точнее этим измерением не установить.

## Инсоляция

Массинг показывает, что стоит. Тень на выбранный час показывает, куда
падает в этот час. Проектировщика же интересует норма: двор считается
пригодным, если солнце стоит в нём не меньше двух часов, и увидеть это,
крутя ползунок времени, нельзя.

Кнопка «Рассчитать за день» во вкладке «Участок» считает по дате из
вкладки «Сцена» с шагом двадцать минут и раскрашивает землю по числу
часов солнца. Доля берётся от открытой земли внутри круга, без пятен
застройки: под домом не двор, и в знаменателе ему делать нечего.

Считается в двух измерениях, без единого луча по треугольникам:
застройка сводится к сетке максимальных высот с шагом три метра, из
точки шагаем в сторону солнца и сравниваем высоту препятствия с высотой
луча над землёй. Участок в 250 м — около двухсот миллисекунд.

Верх цветовой шкалы — максимум этого дня, а не постоянная величина: под
Москвой в июне светло семнадцать часов, и на постоянной шкале двор
упирался в потолок и выходил ровно белым. Недобор норматива красится
терракотой — это единственное место в сцене, где цвет несёт смысл.

**Три ошибки, которых стоил этот расчёт.** Все три давали одну и ту же
картину — «освещено всё и всегда», — и все три нашлись только потому,
что стопроцентная инсоляция в декабре выглядела неправдоподобно.

1. Марш шёл **от** солнца, а не к нему: азимут был сдвинут на π, и
   проверялось, есть ли препятствие там, куда падает тень.
2. Сетка препятствий заводилась нулями, а отметки в сцене отсчитываются
   от нуля в обе стороны — вся застройка ниже датума молча отбрасывалась.
   Пустая ячейка теперь означает отсутствие препятствия, а не нулевую
   высоту.
3. Буфер рельефа **передавался** во владение главному потоку и в
   фоновом отцеплялся; чтение из него давало NaN, и сравнение высот
   всегда было ложным. Рельеф теперь копируется — сотни килобайт против
   молча неверного результата.

Проверяется двумя синтетическими случаями (`scratchpad/ins_test.mjs`,
`ins2.mjs`): точка к северу от сорокаметровой стены получает в декабре
ноль часов, к югу — полные 6.3; замкнутый двор 40×40 м со стенами в
20 м получает ноль в декабре, ноль в марте и 10.3 часа в июне.

## Разметка

Массинг отвечает на вопрос «что здесь стоит». Работа начинается со
второго вопроса — «что здесь делать», и на него нужно уметь ответить
прямо поверх модели. Вкладка «Разметка» даёт четыре инструмента:

- **линия** (<kbd>L</kbd>) — трасса, ось, маршрут; считается длина;
- **площадка** (<kbd>A</kbd>) — контур участка или зоны; площадь и периметр;
- **метка** (<kbd>P</kbd>) — точка, вокруг которой строится радиус;
- **пометить дома** (<kbd>M</kbd>) — клик красит здание акцентом; в сводке
  количество, суммарное пятно и поэтажная площадь.

<kbd>V</kbd> возвращает в режим просмотра. Клавиши читаются по коду, а не
по символу: на русской раскладке `e.key` вернул бы «в» вместо «v».

**Рисование.** Ломаная тянется за курсором — без этого не видно, куда
пойдёт следующий отрезок, и линию приходилось набирать вслепую. Клик
ставит вершину, двойной клик или <kbd>Enter</kbd> заканчивает,
<kbd>Esc</kbd> отменяет незаконченное.

**Правка.** Клик по разметке в режиме просмотра выбирает её: появляются
маркеры вершин, и любую можно перетащить. Без маркеров разметка выглядит
нарисованной намертво — непонятно, из чего она состоит и за что её
брать. На время перетаскивания орбита отключается, иначе вместе с
вершиной едет камера. <kbd>Delete</kbd> удаляет выбранное,
<kbd>⌘Z</kbd> отменяет последнее изменение (тридцать шагов).

**Буфер** правит выбранный объект, а без выбора — последний: радиус
подбирается на глаз по уже нарисованному, а не задаётся вслепую заранее.
Инструмент тут же показывает площадь зоны и сколько зданий в неё попало
(по центру пятна).

Буфер намеренно непрозрачный. Полупрозрачные пятна складываются там, где
перекрываются, и зона из двух отрезков выходит пятнистой.

Вершины садятся только на верх керна: если ловить попадания по всей
сцене, точка вставала бы на крышу дома или на крону дерева.

Пока идёт подъём застройки, выбор отключён — вершины двигает шейдер, а
луч летит по исходным координатам, и попадания были бы неверными.

## Сохранённые участки

Без этого продукт одноразовый: закрыл вкладку — и разметка, пометки и
выбранное место пропали, а собирать участок заново стоит десятков
секунд. Кнопка «Сохранить» в редакторе кладёт участок вместе с разметкой
в список на первом экране; клик по строке открывает его обратно и
восстанавливает разметку после сборки — до неё нет ни сцены, ни
указателя на здания, к которым привязаны пометки.

Одноимённый участок заменяется, а не плодится: пересохранение после
правки — обычное дело, и список иначе быстро зарастает.

Выгрузка в GeoJSON включает разметку, помеченные дома и проектные
объёмы. Помеченный дом отдаётся точкой в центре пятна: контуров в
облегчённой карточке здания нет, и рисовать вместо них габаритный
прямоугольник было бы враньём.

## Проверка разметки

Интерфейс разметки живёт на событиях указателя, и глазами по скриншоту
его не проверить. `MASSING_DRAWTEST=1 npm start` прогоняет весь путь:
рисует линию, проверяет резиновую нитку, выбирает объект кликом, тащит
вершину, отменяет, помечает дома, сохраняет участок и читает его
обратно. Печатает строку `DRAWTEST {...}`.

Прогон обязан дождаться конца анимации роста — иначе половина проверок
падает ложно, потому что выбор в это время отключён. На это ушло два
прогона и одна неверная гипотеза про `requestAnimationFrame`.

Ошибки `setPointerCapture` в выводе — артефакт синтетических событий:
OrbitControls захватывает указатель, которого на самом деле нет. К
продукту отношения не имеют.

## Откуда взяты решения по набору

Токены сняты с живых продуктов через design-inspiration MCP
(`design_extract_tokens`), а не придуманы на глаз.

**Linear** — эталон по мелкой типографике интерфейса:

- отрицательный трекинг на всех кеглях, около −0.011em, и он растёт с
  размером. На нулевом трекинге набор в 12–15 пунктов выглядит
  разреженным: буквы стоят, а не складываются в слово;
- веса 510 и 590 вместо круглых 500 и 600 — иерархия строится мягче, а
  600 в мелком кегле уже читается жирным пятном;
- радиус 2 px доминирует (48 применений из полусотни) — совпало с тем,
  что уже было;
- наведение меняет фон **и** цвет разом. Одна смена цвета читается как
  подсветка текста, одна заливка — как выделение мышью; вместе они
  читаются как «сюда можно нажать»;
- тени почти отсутствуют: `rgba(0,0,0,.03) 0 1.2px 0` — не тень, а
  волосяная линия снизу.

**Felt** (карты) — пара «серифный дисплей + гротеск в интерфейсе» и
акцент, живущий только в подсветке при наведении.

Что из этого легло в проект: оптический трекинг двумя ступенями
(`--track`, `--track-lg`), промежуточные веса, табличные цифры
(`font-variant-numeric: tabular-nums` — без них значение под ползунком
дёргается на каждом шаге, потому что «1» уже «8»), парная ховер-дельта.
Марка набрана моноширинным вразрядку: единственное место, где
моноширинный выходит за пределы чисел, — так первая строка задаёт
экрану тон прибора, а не приложения.

Трекинг снят с моноширинного, капительных подписей и клавиш: цифрам
нужна ширина знака, прописным в подписях — разрядка.

## Оформление

Правки, которые пришлось внести после того, как поверх минималистичной
основы легли разметка и сохранённые участки:

- **Кнопка запуска липнет к низу панели.** `margin-top:auto` прижимает
  её к низу, только пока содержимое помещается; стоило добавить список
  сохранённых участков — и главное действие экрана уехало под обрез.
- **Карта обесцвечена** фильтром на слое тайлов. Цветная карта рядом с
  монохромным инструментом читается как чужая вставка и перетягивает
  внимание, хотя выбирают на ней одну точку. Обесцвеченная становится
  фоном, а единственным цветным остаётся круг участка — то есть ровно
  то, чем сейчас управляют.
- **Вкладок стало четыре**, и на прежней ширине панели слова смыкались
  в одну строку: панель расширена до 296 px, размер вкладок снижен до
  мелкого.
- **Системный `prompt` заменён своим полем** в модальном окне. В
  оболочке он выглядел чужой вставкой — другой шрифт, другие кнопки, —
  и оформление рассыпалось разом.
- **Флажок «Загружать рельеф»** переехал к радиусу: это опция сборки, а
  не хвост списка городов. Заодно пришлось исключить `.check` из
  правила для заголовков разделов — иначе флажок перенимал разрядку и
  капитель и разъезжался на всю ширину.

## Движение интерфейса

Одна кривая на весь интерфейс и три длительности: разнобой в таймингах
читается как неряшливость, даже когда каждый переход сам по себе хорош.

- Разделы панели сворачиваются, и состояние переживает перезагрузку:
  панель длиннее экрана, и чтобы добраться до слоёв, приходилось
  прокручивать мимо солнца и камеры. Заголовки при этом остаются на
  месте — по ним видно, что инструмент вообще умеет.
- Слои разделены на «Объекты» и «Отрисовку»: десять флажков подряд
  требовали читать каждый.
- Под плотностью застройки и коэффициентом плотности идёт шкала —
  «52 %» само по себе ничего не говорит тому, кто не держит в голове
  типовые значения.
- Пока ждём Overpass, по полосе загрузки бежит блик: проценты в это
  время стоят на месте по десять секунд и выглядят зависанием.
- Сообщение о том, что качество снижено, приходит плашкой поверх сцены,
  а не в строку статуса на вкладке, где пользователя может не быть.
- Тёмная плашка вкладок и переключателей не перескакивает, а едет от
  кнопки к кнопке — видно, откуда пришло состояние.
- Флажки нарисованы свои: системный `accent-color` не даёт ни отклика на
  наведение, ни движения при переключении, а список слоёв — главный
  орган управления сценой.
- У ползунка закрашена пройденная часть дорожки: без этого она ничего не
  сообщает о том, где ты находишься.
- Экраны сменяются растворением. Мгновенная подмена двух полноэкранных
  панелей читается как сбой отрисовки.
- Заслонка загрузки растворяется, а не исчезает щелчком: сцена
  собиралась десять секунд, выскакивать рывком ей незачем.
- Клавиши: <kbd>1</kbd> <kbd>2</kbd> <kbd>3</kbd> — виды,
  <kbd>Пробел</kbd> — рост застройки, <kbd>Tab</kbd> — панель,
  <kbd>Esc</kbd> — закрыть. Подсказка всплывает на первой же попытке.

Всё это уважает `prefers-reduced-motion`.

Две грабли, на которых это ловилось:

- **Снимать прозрачность нового экрана по `requestAnimationFrame`
  нельзя.** В неактивном окне кадры не выдаются, и экран остаётся
  невидимым до тех пор, пока на него не переключатся. Таймер тикает
  всегда.
- **`transition: transform` на SVG-группе.** Компас поворачивается
  атрибутом `rotate(a 24 24)`, где центр уже задан. Стоило добавить
  переход, как Chrome начал считать это CSS-трансформацией, и заданный
  в CSS `transform-origin` сложился с центром из атрибута — картушка
  уехала за край. Origin обязан быть нулевым.

## Кровли и мосты

**Скатные кровли** строятся по тегу `roof:shape`: двускатная, вальмовая,
пирамидальная, односкатная, мансардная. Высота берётся из `roof:height`,
затем из `roof:levels`, иначе из пропорции к короткой стороне — у скатной
кровли подъём связан с пролётом, а не с высотой дома. Кровля не надстраивается
сверху, а забирает верх объёма: `height` в OSM меряется до конька.

Направление конька определяется по главной оси пятна. Кровля ставится на
габаритный прямоугольник, поэтому сложные в плане здания остаются плоскими —
проверяется, насколько контур заполняет свой прямоугольник (порог 78 %).
Для непрямоугольного дома скатная кровля по габариту была бы враньём.

**Мосты** (`bridge=yes`) поднимаются над руслом по тегу `layer` и строятся
плитой с толщиной — видна кромка, полотно отбрасывает тень. Раньше путепроводы
лежали прямо на воде.

## Что стоит на керне

Кроме объёмов застройки сцена населена мелочью из тех же данных OSM — она
возвращает масштаб: рядом с машиной сразу понятно, что дом четырёхэтажный,
а не восьми.

| Объект | Откуда |
|---|---|
| Деревья | точки `natural=tree`, аллеи `tree_row`, плюс процедурная посадка внутри полигонов зелени по плотности на тип (лес — дерево на 90 м², парк — на 200, газон — на 420) |
| Транспорт | вдоль осевых линий улиц со смещением на полосу и разрывами |
| Мачты освещения | `highway=street_lamp`, а если их нет — сами вдоль улиц с шагом 38 м |
| Ограды и живые изгороди | `barrier=fence/wall/hedge/retaining_wall` |

Всё инстансингом: тысячи объектов — один вызов отрисовки на тип. Расстановка
детерминированная, при повторной сборке того же участка деревья стоят там же.
Тени отбрасывают только деревья: у машин и мачт они на масштабе квартала
неразличимы, а карту теней удваивают в цене.

**Палитра строго нейтральная.** Слои различаются светлотой, а не цветом: цветные
вода и зелень тянули внимание на себя и спорили с застройкой. Вода отличается
не оттенком, а глянцем — гладкая поверхность ловит отражение неба.

## Движение

Анимации не украшают, а объясняют, что произошло.

- **Рост застройки.** После сборки объёмы поднимаются волной от центра участка
  к краю — сборка читается как действие, а не как мгновенная подмена картинки.
  Считается в вершинном шейдере (атрибуты `aBottom` и `aDelay` плюс uniform
  `uGrow`), поэтому геометрия не пересобирается на каждом кадре, а тени растут
  вместе со зданиями. Повторить — кнопка «Проиграть рост застройки».
- **Подсветка под курсором.** Объём отзывается на наведение до клика, курсор
  меняется на указатель. Луч пускается не чаще раза в 60 мс.
- **Медленный облёт** — тумблер во вкладке «Сцена»: модель поворачивается сама,
  как на витрине, и останавливается, стоит взяться за мышь.
- **Перелёты камеры** между ракурсами — с плавной кривой, а не рывком. Кадр
  подбирается под свободную часть окна: панель управления в расчёт входит,
  поэтому керн не упирается в неё и не обрезается.
- **Интерфейс**: панели въезжают после того, как сцена готова, карточка здания
  и модальные окна всплывают, кнопки отзываются на нажатие.
- При включённом системном «уменьшении движения» все переходы отключаются.

## Выгрузка модели

Кнопки в верхней панели: **PNG**, **GLB**, **OBJ**, **GeoJSON**.

Прежде наружу уходила только застройка и только треугольниками — один
безымянный объект без рельефа, дорог и зелени. Открыть его было можно,
работать с ним нельзя.

Теперь `exportScene()` собирает отдельную сцену выгрузки: те же
геометрии, но разложенные по именованным слоям (`buildings`,
`proposal_volumes`, `terrain`, `roads`, `paved`, `green`, `water`,
`trees`, `fences`, `cars`, `lamps`) и с обычными материалами вместо
экранных. Имена слоёв латиницей — это имена объектов в чужой
программе, кириллица в них живёт плохо.

Два решения, которые стоит помнить:

- **Инстансы запекаются в обычную геометрию.** glTF умеет хранить
  расстановку деревьев расширением `EXT_mesh_gpu_instancing`, но
  читают его не все, и дерево, которое не поняли, приезжает в одном
  экземпляре в начале координат. Запечённая геометрия тяжелее, зато
  открывается везде одинаково.
- **Привязка лежит в `extras` корневого узла**: широта, долгота,
  радиус, оси и строка атрибуции ODbL. Локальные метры сами по себе
  ничего не значат — без привязки модель невозможно поставить на место.

Экранный материал в файл не переносится: зерно и пыль у основания
живут во врезке в шейдер и считаются по мировым координатам. Наружу
уходит равноценный обычный `MeshStandardMaterial`.

Проверка — `MASSING_GLB=/путь/model.glb npm start`: приложение
собирает участок, пишет GLB на диск и выходит. Самопроверка говорит
лишь, что экспортёр не упал; валиден ли glTF, видно только по разбору
самого файла. На Замоскворечье R = 250 м: 5.3 МБ, 25 узлов, 14 мешей,
габарит ±252 м, NaN нет.

Зависимости экспортёра лежат в `vendor/exporters/`. `GLTFExporter`
тянет за собой `vendor/utils/TextureUtils.js` — без него модуль просто
не загружается, а в консоли видно только `ERR_FILE_NOT_FOUND` без
имени файла.

## Живая перезагрузка

Сервер следит за `index.html` и `app/*` и сообщает браузеру о правках через SSE
(`/__events`). Работает только на localhost.

- **Правка `.css`** — стили подменяются на лету, модель остаётся в сцене,
  внизу мигает плашка «стили обновлены».
- **Правка `.js` или `.html`** — страница перезагружается, но **возвращается ровно
  туда же**: тот же участок, ракурс, проекция, дата и время солнца, состояние слоёв,
  текст в поле запроса и уже размещённые проектные объёмы. Данные берутся из кэша,
  так что пересборка занимает около секунды.
- Если в момент правки идёт запрос к нейросети, перезагрузка откладывается до ответа —
  иначе она оборвала бы оплаченный запрос.

Состояние живёт в `sessionStorage` (снимок для перезагрузки) и `localStorage`
(последний участок).

## Ограничения

- Модель настолько точна, насколько заполнен OSM. Доля восстановленных высот
  показана в статистике — если она мала, к цифрам плотности стоит относиться как
  к оценке.
- Формы крыш не строятся: все объёмы плоские (схема Simple 3D Buildings учитывается
  только в части `building:part`).
- Рельеф из открытых DEM имеет разрешение около 30 м — мелкие перепады, подпорные
  стенки и террасы не воспроизводятся.
- Показатели считаются по всему кругу, включая улицы и воду, а не по границам
  землеотвода. Здания на границе учитываются той частью пятна, что попала внутрь.

## Приложение для macOS

Кроме браузерной версии есть десктопная оболочка на Electron — иконка в доке,
обычное окно, никакого терминала.

```bash
npm install      # один раз
npm start        # запустить
npm run dist     # собрать МАССИНГ.app → dist/mac-arm64/
npm run dmg      # собрать образ для переноса на другую машину
```

Оболочка отдаёт файлы через собственную схему `app://`, а не через `file://`
и не через локальный сервер: ES-модули и веб-воркеры требуют настоящего origin,
а постоянный `app://massing` позволяет кэшу участков в IndexedDB переживать
перезапуск.

**Своя кэш-память.** У приложения отдельное хранилище от браузера, поэтому первый
запуск качает данные заново, даже если в браузере участок уже открывался.

**CORS.** Overpass и часть сервисов не возвращают заголовок доступа на
нестандартную схему `app://`. Оболочка дописывает его сама — но только для
перечисленного в `desktop/main.js` списка доменов.

**Самопроверка.** `MASSING_SELFTEST=1 npm start` соберёт участок и напечатает
в терминал строку `SELFTEST {...}` с результатом — удобно после правок.

Сборка не подписана Apple: при первом запуске на чужой машине macOS попросит
подтверждение через «Системные настройки → Конфиденциальность и безопасность».
